# Kernel feature and serve-patch flags (Qwen3.8-2B integration, 2026-09-22)

Runtime switches for the integrated kernel set (fused GDN decode/prefill,
bf16 coopmat qmm prefill, q4 gemv xpack) and the vendored mlx-lm serve
patches. All default to the shipped configuration; the flags exist for
A/B gating and qualification, not for normal operation.

## GPU kernel flags (backend, wheel)

| Flag | Default | Effect |
|---|---|---|
| `MLX_OMARCHY_KV_DIRECT` | on (`1`) | Direct decode KV window storage in fused chains. `0` composes ops; output-neutral. |
| `MLX_OMARCHY_KV_INPLACE` | on (`1`) | A direct decode KV window writes new rows into the cache buffer when the update holds the last handle to it, so a decode token no longer copies the whole cache. `0` always copies; output-neutral. |
| `MLX_OMARCHY_QMM_GEOM` | unset (`2x8w2` on G13G, G13C, G14C, and non-BMG discrete GPUs; `2x16w2` on BMG; `2x16` on other qualifying 512-thread parts; `2x4` elsewhere) | Read once. Selects the columns-per-workgroup geometry of the bf16 subgroup 4-bit/group-64 decode kernels (`Word`, `Multi`, dedicated 1-pass interleaved `SwiGLU`, `ResNorm`, and `OutgateResNorm`). Every default-eligible geometry (`2x4`, `2x4w2`, `2x8w2`, `2x16`, `2x16w2`) runs the same strided per-lane chain, so outputs are bit-identical to `2x4`. Experimental overrides `2x16kcont` and `2x16kcs16` assign contiguous K-chunks per lane, reassociating FP32 sums at `K >= 1024` (`+/-1` bf16 ULP, flipping exact greedy ties on 9B); they are **not bit-identical** and are excluded from every default selection. `2x8w2` uses 2 rows/slot x 8 slots (256 threads/WG, 16 cols/WG) with hoisted `uvec2` weight loads, dedicated 1-pass interleaved SwiGLU sharing `x`, and 1-pass W2 ResNorm without `reg_x[16]`. Byte identity for default-eligible geometries and non-bit-identity of `2x16kcont` are pinned by `tests/omarchy/test_qmm_geometry.cpp`, `tests/omarchy/test_qmm_kcont_parity.py`, and `tests/omarchy/test_vram_activations.cpp`. |
| `MLX_OMARCHY_FUSED_GEMV`, `MLX_OMARCHY_FUSED_TRIO` | on; `FUSED_GEMV` off on G16G and G14C | Read live, per call, for the device that executes the work. `0` keeps every decode QuantizedMatmul, dense bf16 decode GEMV group and Add on the per-node path (`FUSED_GEMV`), and f16 RMSNorm rows, the SwiGLU chain and RoPE pairs on their standalone kernels (`FUSED_TRIO`; the RMSNorm and SwiGLU legs apply at any row count, so f16 prefill too); the two are independent, and `MLX_OMARCHY_FUSED_CHAIN=0` covers both. Unset, `FUSED_GEMV` is off on the parts of `omarchy::fused_gemv_off_default_part` (G16G Apple M4 and G14C Apple M2 Max), where the per-node decode GEMV is faster, and `FUSED_TRIO` is on on every part (on G16G turning the trio off moved perplexity away from the reference; receipts/2026-11-01-m4-decode-defaults, `numerics-gate/`); `1` forces `FUSED_GEMV` on there. |
| `MLX_OMARCHY_ROPE_NORM_PAIR` | off (unset) | Read live. `1` opts the norm-carrying bf16 form into pairing a layer's two `rope_rms_norm` launches (Q and K sides) into one dispatch (`shaders/fast_rope_norm_pair.comp`; one workgroup per rotation row per side, KV-window direct redirect kept). Output-neutral: bit-exact greedy token IDs against the solo path (Qwen3-4B-Instruct-2507-4bit, ctx512, gen64, 5-pair interleaved ABBA, IDs `a6fad159dfa90047`). Measured median 34.27 tok/s pair vs 34.55 solo (-0.81%) on a 16-inch M1 Max at `a0ec2c21a`, so the pair stays opt-in until it shows a matched speedup. `0` or unset keeps the solo dispatches; `MLX_OMARCHY_FUSED_TRIO=0` disables the whole scan. |
| `MLX_OMARCHY_QMM_RESIDUAL_NORM` | on at widths 256, 2048, and 4096 (plus 2560 on G13C, G14C, and discrete GPUs) on capable devices | Read live. Folds trailing single-row bf16 `ResidualAdd` + `RMSNorm` into quantized decode QMM. Requires 32-lane subgroup arithmetic and the workgroup limits for the selected kernel. `0` disables; `1` bypasses the default width list, not dispatch requirements. `MLX_OMARCHY_FUSED_CHAIN=0` disables both. |
| `MLX_OMARCHY_QMM_EPILOGUE_GEMV` | on where multi-weight fused GEMV defaults off; off elsewhere | Read live per device. Allows single-member decode QMM groups carrying an Add epilogue, independent of the residual-norm width policy. On G14C (unless `MLX_OMARCHY_FUSED_GEMV=0` is explicitly set) balanced bf16 groups also plan: 3-member QKV groups with widths >= 512 and max/min <= 8, and 2-member pairs with max/min <= 4 — MLP `gate`/`up` pairs and the two pairs a 4-member GDN `in_proj` window (for example `[6144, 2048]` + `[16, 16]`) splits into. Members outside a passing pair keep the per-node path. `0` disables; `1` enables. `MLX_OMARCHY_FUSED_CHAIN=0` disables both. |
| `MLX_OMARCHY_NO_MLXLM_WARNING` | unset (warning on) | `1` silences the one-time stderr warning printed at the first GPU open when the mlx-lm beside the loaded libmlx has no omarchy serve patches (no `mx.fast.gated_delta_update` route in `mlx_lm/models/gated_delta.py`). No effect on results. |
| `MLX_OMARCHY_NO_COOPMAT` | unset (route on) | `1` disables the bf16 coopmat qmm-prefill route; output-neutral. |
| `MLX_OMARCHY_NO_MATMUL_RB_F32` | unset (route on) | Read once. A float32 matmul with `matrix_m >= 32` and no bias that neither cooperative-matrix route takes (a driver without `VK_KHR_cooperative_matrix`, or an f32 product the coopmat gates decline) runs the f32 build of the 64x64 register-blocked tile (`shaders/matmul_rb.comp -DUSE_F32=1`, `MatmulRbF32`) instead of the 16x16 tile. Same per-output arithmetic, so the stored bits are unchanged. `1` restores the 16x16 tile. |
| `MLX_OMARCHY_NO_QMM_FMA_BF16` | unset (route on) | Read once. Where the cooperative-matrix qmm route is not reachable for the call (no fp32 cooperative matrix, subgroup size other than 32, too little shared memory, or `MLX_OMARCHY_NO_COOPMAT=1`), a multi-row bf16 4-bit/group-64 transposed `quantized_matmul` runs the bf16 build of the scalar-FMA prefill kernel (`shaders/qmm_fma.comp -DUSE_BF16=1`, `QmmPrefillFmaBF16`, precise twin from 1024 rows), the route f16 already takes, instead of the scalar 16x16 tile kernel. `1` restores the tile kernel. Measured on the M4 Mac mini with the cooperative matrix off: receipts/2026-11-01-m4-bf16-qmm-fma. |
| `MLX_OMARCHY_QMM_BF16W` | on for G16S where the cooperative-matrix qmm route is reachable, unset (off) elsewhere | Read live. A bf16 4-bit/group-64 transposed `quantized_matmul` against one 2D weight, with at least 1024 rows (or 512 rows when the weight has at most 2^26 elements, `omarchy::qmm_bf16w_rows_ok`), runs in two passes: the affine Dequant kernel writes the weight as bf16 into an encoder temporary, and the dense bf16 matmul (`MatmulBF16Coopmat`) contracts x with it. The single-kernel cooperative-matrix route keeps the dequantized weight in float32; the two-pass route rounds it to bf16 first, which is what the Metal backend does, so the output is not bit-equal to the single-kernel route. Unset follows `omarchy::qmm_bf16w_default_part` in `device.h`, `0` keeps the single-kernel route, any other non-empty value selects the two-pass route on any part where it applies. Below the row rule the dequantize pass costs more than it saves (256 rows: 1.76 against 3.03 ms at 4096x4096). Qwen3-8B-4bit on G16S: perplexity 8.7437 to 8.7422 on wikitext-2, prefill +15.8 percent at 2060 tokens and +11.3 percent at 8010 (`receipts/2026-11-15-m4-pro-g16s-qmm-bf16w`). |
| `MLX_OMARCHY_NO_COOPMAT_GDN` | unset (route on) | `1` forces the GDN prefill T>=64 token chunks onto the two-pass scan kernel instead of the single-pass coopmat kernel (2026-09-23 install, receipts 2026-09-23-gdn-coopmat-install). Wheels built before 2026-09-29 carry a defective chunk inverse (N^6 computed as 0) that turns real-text prefill logits NaN; set `1` on those. The fixed kernel is held to the contract below against the scan route (receipts/2026-09-29-prefill-gdn-fix-sdpa-direct.md). 2026-10-03: the captured 27B operands (layer0/layer12, incl. g=5.9e-11) became checked-in fixtures (`tests/omarchy/fixtures/gdn_coopmat`) alongside the fp64 sweep — fused state max-err 1.4e-5 / 1.7e-6 vs fp64, zero NaN; gate floor lowered to FLT_MIN (2026-09-29..10-02 wheels clamp at 1e-6, mis-stating sub-floor decays ~1.7e4) and the batch kernel's wave store->read accesses are now explicitly ordered (receipts/2026-10-03-gdn-coopmat-fix). |
| `MLX_OMARCHY_GDN_DECODE_BATCH` | unset (route on) | `0` restores the `B == 1` gate on the fused GDN decode kernel, so batched decode (B > 1, T = 1, no padding mask) runs the composed per-token chain again. On by default since 2026-10-07: oMLX c4 aggregate 58.1 -> 71.8 tok/s on an M1 Max; each batch row is bit-identical to the same row decoded alone. |
| `MLX_OMARCHY_SDPA_DECODE_BATCH` | unset (route on) | Read live. `0` restores the `batch == 1` gate on the native bf16 SDPA decode kernel, so batched single-query decode runs the ~10-dispatch composition again. The kernel walks the batch on workgroup z; each row is bit-identical to the same row decoded alone (and to the composition, which the bf16 arm reproduces exactly). |
| `MLX_OMARCHY_SDPA_DECODE_BOOL_MASK` | unset (route on) | Read live. `0` restores the composed route for two-stream BF16 single-query attention with 128-wide heads under a mask; every other value, including unset and empty, keeps the fused shader, which applies the BF16 additive mask, including the finite floor used for boolean masks, before FP32 softmax. Unsupported layouts and other shapes still use the composed route. On by default since 2026-11-20: 16-inch M1 Max, five AB and BA pairs, two streams 53.895 -> 68.934 tokens a second, token digests identical, zero GPU timeouts. One stream is unchanged at every cap; two streams gain 26 to 34 percent. |
| `MLX_OMARCHY_KV_MASKLESS` | unset (on) | mlx-lm patch (`scripts/patch-mlx-lm-kv-maskless.py`, 0.32 series only). `0` makes `BatchKVCache.make_mask(1)` return the array mask again when no row is padded. With it on, unpadded batched decode passes no mask, so the native SDPA decode kernel stays reachable; padded batches, prefill and caches whose `left_padding` was assigned from outside the class keep the mask. The 0.31.3 series ships without it: the patchers anchor on the 0.32 BatchKVCache API and 0.31.3's older class predates it (a batched 0.31.3 user keeps upstream masking — slower composed SDPA, never wrong; the served mlx-lm route is single-concurrency). |

| `MLX_OMARCHY_ROTKV_MASKLESS` | unset (on) | mlx-lm patch (`scripts/patch-mlx-lm-rotkv-maskless.py`, after kv-host-offset, 0.32 series only — see the KV_MASKLESS row for the 0.31.3 scope). `BatchRotatingKVCache.make_mask(1)` returns None while the sliding window is not binding and no row is padded (a host mirror of `left_padding`; also requires no rotation and no right-padding lengths), so every sliding-window layer of a batched decode keeps the native SDPA decode kernel reachable; padded, rotated and prefill states, window-bound and `return_array` calls, and caches whose `left_padding` was assigned from outside the class keep the array mask. `0` restores the mask. 13-inch M1, 2026-10-18 serve-loop census (gemma-4-E4B): the all-True mask cost +568 dispatches and +5.18 ms per token across the 35 sliding-window layers (76.67 -> 71.49 ms/token with the mask gone, part of the 18.6% serve-loop gap); token ids equal; receipt `receipts/2026-10-18-serve-loop-13inch/`. |
| `MLX_OMARCHY_ROPE_VECTOR_OFFSET` | unset (on) | Read live. | `MLX_OMARCHY_ROW_REDUCE` | unset (on) | Read live. | `MLX_OMARCHY_SDPA_SPLIT_PV` | width 128: on up to 2048 keys on G14C and G13C, up to 1280 keys on G15S and up to 16384 keys on G16S, off on G13G; width 256: on while key-value heads times 128-key blocks is at most 16 on G13G, 64 on G13C (two workgroups per GPU core), 68 on G14C and 36 on G15S (the measured edges), no default on other parts | Read live. - `patches/mlx-lm-0.32/` — the same series rebuilt for the mlx-lm 0.32 API
  line (commit 94cdcae, the pin oMLX uses; the PyPI 0.32.0 wheel carries
  byte-identical patch-site files), so oMLX can run on the Omarchy
  stack. The apply script picks it when `mlx_lm.generate` defines
  `StopSequences`. conv-ring has no 0.32 port; the script refuses
  `MLX_OMARCHY_CONV_RING=1` there before touching the venv. Receipt:
  receipts/2026-10-02-mlx-lm-032. Token note: the 0.32 stack does not
  reproduce the 0.31.3 stack bit-for-bit on every prompt (upstream
  rescaled the q/k-norm eps, and the raw decode route is conditional);
  on the T6001 10-prompt contract corpus, 3/10 Qwen3.8-2B prompts flip
  one near-tie token. The quality gate (harness v2 GSM8K/IFE vs the
  shipping stack) passed within its pre-declared noise band, which is
  what the acceptance bar below requires for a token change; 4B/9B are
  bit-identical and perf is neutral.
- `mlx-lm-gated-delta-fast-route.patch` — **default ON.** Routes
  `mx.fast.gated_delta_update` in mlx-lm 0.31.3 to the fused kernel in the
  mlx-omarchy wheel. Required for the measured serve numbers.
- `patch-mlx-lm-gdn-raw-repeat.py` — **default ON on all chips.** The
  Qwen3.5-9B fused raw decode route (+31-35% on G14-class; +35-43% on G13)
  runs at Hk != Hv inside the backend: the tiled decode kernel on the f32
  A_log route reads key head j / (Hv / Hk) itself (on G14C, G13C and G16S the untiled
  prefetch kernel does, see `MLX_OMARCHY_GDN_PF_GQA`), and
  `MLX_OMARCHY_GDN_GQA_DECODE=0` makes the backend expand q and k instead.
  `MLX_OMARCHY_GDN_RAW_REPEAT=1` expands them in Python before the call. The published-wheel
  audit measured 99.51% teacher-forced agreement; all first free-run
  divergences were within one bf16 ULP. See docs/numerics-gate.md for the
  criteria and receipts/2026-10-04-gdu-bar-audit/README.md for evidence.

  /path/to/venv`.
- `mlx-lm-greedy-prune.patch` — **default ON (OFF on G14C).** Greedy decode steps
  (default sampler, no logits processors, one input token) of tied
  4-bit/group-64 Qwen3.5-family heads take `mx.fast.greedy_quantized_argmax`:
  a certified bound on a 3-bit code sketch skips the rows that cannot hold
  the argmax, so the token equals `argmax(logits - logsumexp(logits))`
  bit for bit while most of the vocabulary projection is never read.
  `logprobs` stay lazy and run the full projection only when a consumer
  evaluates them. On G14C (Apple M2 Max) this defaults off because full
  projection + argmax was measured faster; override with
  `MLX_OMARCHY_NO_GREEDY_PRUNE=0` (force on) or `=1` (force off) at run time.
  The sketch holds 3 bits per
  code, three quarters of the packed codes (190.7 MB for Qwen3.8-2B's
  248320-row head), built once per process at the first greedy call.
- `mlx-lm-server-skip-logprob-read.patch` (0.32 series only) — **default
  ON.** The server's decode loops read the sampled token's logprob off the
  device for every token — a gather graph plus a blocking `.item()` read,
  3.48 ms/token of the 19% serve-loop decode gap on a 13-inch M1 with
  gemma-4-E4B (receipt `receipts/2026-10-18-serve-loop-13inch/`) — even when the request asked for neither `logprobs` nor
  `top_logprobs > 0`; the handler reads `Response.logprob` only when
  `logprobs` is set and `Response.top_tokens` only when `top_logprobs >
  0`. The per-request flag rides the existing `batch_results` entry (and a
  hoisted local on the single path); skipped Responses carry
  `logprob=None` / `top_tokens=None`. Generated token ids are unchanged
  (`tests/test_server_logprob_skip.py` drives the real ResponseGenerator
  on the CPU tiny model). Kill switch `MLX_OMARCHY_SERVER_LOGPROB_READ=1`
  (read once at import) restores the upstream always-read; the 0.31.3
  series keeps upstream behavior.
- `mlx-lm-kv-presize.patch`, default on. `KVCache` grows by one block of 256 tokens for every prefill chunk, and each growth
  builds the larger buffer while the old one is still alive. `generate_step` now gives each `KVCache` a reserve: the prompt
  plus the first 1024 decode tokens, or `max_tokens` when that is smaller. Prefill then allocates the cache once and the
  copies of the growing cache stop. The decode part has a bound, so a short prompt with a large `max_tokens` does not hold
  KV it will not use. A quantized cache (`kv_bits`) and the other cache classes keep the upstream growth.
  `MLX_OMARCHY_KV_PRESIZE=0` (read per call) restores the upstream growth. The batched server route (`BatchKVCache`) is not
  covered by this patch. The automatic prefill chunk is chosen before the cache exists, so it cannot count the cache. After
  the first chunk makes the cache resident, `generate_step` chooses the chunk again from the headroom that is left, minus a
  1 GiB workspace that matches the serve budget. The new chunk is never larger than the first one. An explicit
  `prefill_step_size` and `kv_bits` skip this step.
- `mlx-lm-speculative-verify.patch` (both series; `patches/` for 0.31.3 and `patches/mlx-lm-0.32/` for the 0.32 line).
  `speculative_generate_step` runs each verify pass (the last
  accepted token plus the drafted tokens) with full logits, since the last-logits patches trim a cached forward to its
  final row, and with `MLX_OMARCHY_QMV_SMALL_T` set to the pass length when it is unset. The patch never writes
  `MLX_OMARCHY_SDPA_SPLIT_ROWS`: unset now runs the split-K rows route wherever the split route engages (the new
  default), and an explicit value still stays fixed for the whole process.
  With the flag set to `1`, each attention row equals the single-token decode kernel's result (the flag row
  names the key counts where that holds only up to summation order). The whole verify pass is not bit-identical to plain
  decode in every measured cell: with the flag set to `1` the greedy ids differed from plain decode for Qwen3.8-9B at about 1000
  tokens (code) and at about 5000 tokens (code and quote), and in one draft-model chat row (9B target, 2B draft, G13C);
  with the flag unset they differed in nine more cells (five arms have unknown ids). The cause is not isolated
  (`receipts/2026-11-15-sdpa-split-rows/README.md`). Layers
  whose cache cannot be trimmed (the Qwen3.5 gated-delta and conv state) are restored and the accepted tokens replayed.
  With no draft model, `MLX_OMARCHY_PROMPT_LOOKUP=K` (1 to 7, read per call by `stream_generate`, so `mlx_lm.generate`
  too) drafts up to K tokens from the latest earlier match of the last 3 or 2 tokens in the prompt and output. Lookup
  drafts only while its first token has been right at least 30% of the time recently; plain steps keep scoring it, so
  chat-style text without repeats runs as plain decode. Unset, empty or `0` keeps plain decode, and so does a set
  `max_kv_size`: the speculative route builds an unbounded cache, so a bounded run stays on plain decode and keeps its
  `RotatingKVCache`. The batched server route is not covered.
- The patches are idempotent and fail loudly on mlx-lm version drift.

## Acceptance bar

Cross-host digest equality is not a gate (see README performance section
and `ane-linux-experiments` receipts 2026-09-22-qwen38-integration /
2026-09-22-qwen38-correctness): per-host determinism plus logit-level
equivalence (≤ 2 bf16 quanta) is.
