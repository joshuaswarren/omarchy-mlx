# Kernel feature and serve-patch flags (Qwen3.8-2B integration, 2026-09-22)

Runtime switches for the integrated kernel set (fused GDN decode/prefill,
bf16 coopmat qmm prefill, q4 gemv xpack) and the vendored mlx-lm serve
patches. All default to the shipped configuration; the flags exist for
A/B gating and qualification, not for normal operation.

## GPU kernel flags (backend, wheel)

| Flag | Default | Effect |
|---|---|---|
| `MLX_OMARCHY_KV_DIRECT` | on (`1`) | Direct decode KV window storage in fused chains. `0` composes ops; output-neutral. |
| `MLX_OMARCHY_NO_COOPMAT` | unset (route on) | `1` disables the bf16 coopmat qmm-prefill route; output-neutral. |
| `MLX_OMARCHY_NO_COOPMAT_GDN` | unset (route on) | `1` forces the GDN prefill T>=64 token chunks onto the two-pass scan kernel instead of the single-pass coopmat kernel (2026-09-23 install, receipts 2026-09-23-gdn-coopmat-install). Wheels built before 2026-09-29 carry a defective chunk inverse (N^6 computed as 0) that turns real-text prefill logits NaN; set `1` on those. The fixed kernel is held to the contract below against the scan route (receipts/2026-09-29-prefill-gdn-fix-sdpa-direct.md). 2026-10-03: the captured 27B operands (layer0/layer12, incl. g=5.9e-11) became checked-in fixtures (`tests/omarchy/fixtures/gdn_coopmat`) alongside the fp64 sweep — fused state max-err 1.4e-5 / 1.7e-6 vs fp64, zero NaN; gate floor lowered to FLT_MIN (2026-09-29..10-02 wheels clamp at 1e-6, mis-stating sub-floor decays ~1.7e4) and the batch kernel's wave store->read accesses are now explicitly ordered (receipts/2026-10-03-gdn-coopmat-fix). |
| `MLX_OMARCHY_GDN_DECODE_BATCH` | unset (route on) | `0` restores the `B == 1` gate on the fused GDN decode kernel, so batched decode (B > 1, T = 1, no padding mask) runs the composed per-token chain again. On by default since 2026-10-07: oMLX c4 aggregate 58.1 -> 71.8 tok/s on an M1 Max; each batch row is bit-identical to the same row decoded alone. |
| `MLX_OMARCHY_SDPA_DECODE_BATCH` | unset (route on) | Read live. `0` restores the `batch == 1` gate on the native bf16 SDPA decode kernel, so batched single-query decode runs the ~10-dispatch composition again. The kernel walks the batch on workgroup z; each row is bit-identical to the same row decoded alone (and to the composition, which the bf16 arm reproduces exactly). |
| `MLX_OMARCHY_KV_MASKLESS` | unset (on) | mlx-lm patch (`scripts/patch-mlx-lm-kv-maskless.py`, 0.32 series only). `0` makes `BatchKVCache.make_mask(1)` return the array mask again when no row is padded. With it on, unpadded batched decode passes no mask, so the native SDPA decode kernel stays reachable; padded batches, prefill and caches whose `left_padding` was assigned from outside the class keep the mask. The 0.31.3 series ships without it: the patchers anchor on the 0.32 BatchKVCache API and 0.31.3's older class predates it (a batched 0.31.3 user keeps upstream masking — slower composed SDPA, never wrong; the served mlx-lm route is single-concurrency). |
| `MLX_OMARCHY_KV_HOST_OFFSET` | unset (on) | mlx-lm patch (`scripts/patch-mlx-lm-kv-host-offset.py`, after kv-maskless, 0.32 series only — see the KV_MASKLESS row for the 0.31.3 scope). `BatchKVCache` stores `offset` as an array built from its host mirror (same int32 values) after every in-class update, so the RoPE trig gate reads it without the per-call `rope_offset_scalar` host join a lazy device offset forces. Outside assignments clear the mirror and keep the assigned array. `0` keeps the lazy device offset. `BatchRotatingKVCache` keeps the same mirror (`scripts/patch-mlx-lm-rotkv-host-offset.py`), rebuilt once from the device value at the first decode step after an outside assignment such as `filter`, and `scripts/patch-mlx-lm-gemma4-rope-offset.py` makes gemma-4 hand an array offset to RoPE as is instead of copying it with `mx.array(cache.offset)` (a Copy node with a primitive, which the gate treats as in flight). 13-inch M1, gemma-4-E4B, BatchGenerator against `bench_decode` (2026-10-20, receipts/2026-10-20-serve-gap-rope-offset): 24 `rope_offset_scalar` joins and 20 extra submissions per token before, 0 after; the served-generator gap of +3.83 ms per token (6 percent) closed to -0.12 ms (not real), token ids unchanged. 16-inch M1 Max, 2026-10-07: BatchGenerator B=1 13.56 -> 11.84 ms/token. |
| `MLX_OMARCHY_ROTKV_MASKLESS` | unset (on) | mlx-lm patch (`scripts/patch-mlx-lm-rotkv-maskless.py`, after kv-host-offset, 0.32 series only — see the KV_MASKLESS row for the 0.31.3 scope). `BatchRotatingKVCache.make_mask(1)` returns None while the sliding window is not binding and no row is padded (a host mirror of `left_padding`; also requires no rotation and no right-padding lengths), so every sliding-window layer of a batched decode keeps the native SDPA decode kernel reachable; padded, rotated and prefill states, window-bound and `return_array` calls, and caches whose `left_padding` was assigned from outside the class keep the array mask. `0` restores the mask. 13-inch M1, 2026-10-18 serve-loop census (gemma-4-E4B): the all-True mask cost +568 dispatches and +5.18 ms per token across the 35 sliding-window layers (76.67 -> 71.49 ms/token with the mask gone, part of the 18.6% serve-loop gap); token ids equal; receipt `receipts/2026-10-18-serve-loop-13inch/`. |
| `MLX_OMARCHY_ROPE_VECTOR_OFFSET` | unset (on) | Read live. Forward RoPE (and `rope_rms_norm`) with a per-batch `[B]` int32 offset runs the fused kernel instead of the composition plus a host join per call; every batch row equals a scalar-offset call on that row bit for bit (`tests/omarchy/test_fast_ops.cpp`). `0` routes vector offsets back to the composition. With `MLX_OMARCHY_KV_HOST_OFFSET`, 16-inch M1 Max, 2026-10-07: oMLX c4 70.0 -> 84.9 tok/s, BatchGenerator B=4 zero host joins per step; c1 unchanged (A/A-controlled cell). |
| `MLX_OMARCHY_BATCH_GREEDY` | unset (off) | mlx-lm patch (`scripts/patch-mlx-lm-batch-greedy-head.py`, 0.32 line). Opt-in. `1` makes a `GenerationBatch` whose rows all sample greedily without logits processors take each token from the pruned greedy head (`mx.fast.greedy_quantized_argmax`, one dispatch per row; same token as the full-logits argmax) and leave the logprobs lazy. On the 16-inch M1 Max (2026-10-07) it cost +1.9% ms/token at B=1 and +1.6% at B=4 in-process and -2.5% at oMLX c1; only oMLX c4 gained (+4.7%). |
| `MLX_OMARCHY_QMV_BATCH` | unset (on) | Read live. A bf16 `[B, 1, K]` decode batch (2 <= B <= 4) against one transposed 2D 4-bit/group-64 weight runs `QmmVecQ4WordSubgroupBatch4BF16`, which reads each weight word once per block instead of once per row; each row keeps the single-row chain and must match the per-row kernel bit for bit (`tests/omarchy/test_qmv_batch.cpp`). `0` restores the per-row kernel. 16-inch M1 Max, 2026-10-07: BatchGenerator B=4 27.4 -> 25.6 ms/step, oMLX c4 89.9 -> 92.9 tok/s, c1 unchanged, row digests unchanged. |
| `MLX_OMARCHY_QMV_SMALL_T` | unset (off) | Read live. A number from 2 to 8 (larger values count as 8) sends a batch-1 bf16 `[1, T, K]` pass with 2 <= T <= that number, against one transposed 2D 4-bit/group-64 weight, to `QmmVecQ4WordSubgroupBatch4BF16` in blocks of up to four rows instead of the coopmat prefill tile. The rows of such an x sit at the same strides as a `[T, 1, K]` decode batch, so no copy is made. Each row matches the single-row GEMV bit for bit (`tests/omarchy/test_qmv_batch.cpp`), not the coopmat chain, so the route is opt-in until a numerics decision (`receipts/2026-09-29-jwm1-qmm-small-m-negative.md`). Unset, empty or `0` keeps the shipped route; `MLX_OMARCHY_QMV_BATCH=0` also turns it off. No measured speed claim yet. |
| `MLX_OMARCHY_ROW_REDUCE` | unset (on) | Read live. On by default: a float32, float16 or bfloat16 Sum over a row-contiguous suffix of at least 256 elements runs `shaders/reduce_row.comp`, one 256-wide workgroup per output row and a fixed association order, so the bits repeat on every run. A one-output reduce such as the mean in a batch 1 float32 norm runs as one dispatch instead of two serial ones. `0` restores the serial kernels. Max and Min keep the serial route. Sum changes in the last bits because the association differs, and the error against a float64 reference is smaller (`overlay/tests/omarchy/test_reduce_row.cpp`). See [known-issues.md](KNOWN-ISSUES.md#sum-over-a-long-row-row-reduce-route-on-by-default) for the models whose output changes. |
| `MLX_OMARCHY_ARGREDUCE_CHUNKED` | on for G14C, unset (off) elsewhere | Read live. Unset, G14C (the Apple M2 Max) takes the chunked route and every other part keeps the single-workgroup kernel (`omarchy::vocab_tail_chunked_default`); `1` turns it on and `0` off on any part. The chunked route sends a float32, float16 or bfloat16 ArgMax or ArgMin over the last axis of a row with 8192 to 1048576 columns to two dispatches: `shaders/argreduce_chunk.comp` (one workgroup per 4096-column chunk writes a value and index pair) and `shaders/argreduce_combine.comp` (one workgroup per row merges the pairs). The index is the same as the single-workgroup kernel for every input, including ties, NaN (the first NaN wins), infinities and signed zeros (`tests/omarchy/test_vocab_tail.cpp`). A 248320-column logits row has 61 chunks instead of one workgroup. Integer inputs and shorter or longer rows keep the single-workgroup kernel. With `MLX_OMARCHY_LSE_CHUNKED` it raised Qwen3.5-9B 4-bit decode on a 14-inch M2 Max by about 3 to 4 percent (`receipts/2026-10-23-vocab-tail-g14c`). |
| `MLX_OMARCHY_LSE_CHUNKED` | on for G14C, unset (off) elsewhere | Read live. Unset, G14C takes the chunked route and every other part keeps the single-workgroup kernel (`omarchy::vocab_tail_chunked_default`); `1` turns it on and `0` off on any part. The chunked route sends a float32, float16 or bfloat16 LogSumExp over a row with 8192 to 1048576 columns to `shaders/logsumexp_chunk.comp` (one workgroup per 4096-column chunk writes its maximum and its sum of exponentials) and `shaders/logsumexp_combine.comp` (one workgroup per row merges them with `s = sum(s_i * exp(m_i - m))`). The sums associate differently from the single-workgroup kernel, so the bits can differ in the last places; the test compares the error against a float64 reference with the single-workgroup error. NaN, infinite and all negative infinity rows return what the single-workgroup kernel returns. |
| `MLX_OMARCHY_SDPA_DECODE_SPLIT` | on from 128 keys on G13G, from 320 keys on G13C, from 320 keys on G14C; unset (off) elsewhere | Read live. Runs the bf16 single-query decode attention of head width 128 (batch 1, one query token, 1, 2, 4 or 8 query heads per key-value head, up to 1,048,576 keys, a 32-lane subgroup device, K element offset and strides multiples of 8 and V offset and strides even) as two dispatches: `shaders/sdpa_decode_split_p1.comp` (one 128-thread workgroup per key-value head and block of 128 keys: scores with sixteen 16-byte K loads, block softmax with subgroup reductions, block-weighted values, one K and V read for all query heads of the group) and `shaders/sdpa_decode_split_p2.comp` (one workgroup per query head folds the blocks and stores bf16). The fused kernel it replaces is one 1024-thread workgroup per query head and walks the keys serially (about 0.7 microseconds per key on the Apple M1). Float32 arithmetic in a different order, so the output is not bit-equal to the fused kernel; `tests/omarchy/test_sdpa_split.cpp` gates the error against a float64 reference. Below the per-part key count the fused kernel is faster (the split route costs two dispatches, 79 to 90 microseconds per call up to 512 keys and 89 to 113 at 1024 keys). Any non-empty value other than `0` forces the route at every length it covers, `0` keeps the fused kernel (and the composition above 7168 keys), and an empty value counts as unset. The route accumulates unnormalized float32 sums per block, so bf16 values above about 2^121 can overflow them; set the flag to `0` for such inputs. The part thresholds are `sdpa_split_min_keys` in `device.h`; the measurements are in `receipts/2026-10-23-sdpa-split-decode`. |
| `MLX_OMARCHY_SDPA_SPLIT_PV` | on up to 2048 keys on G14C and G13C, off on G13G | Read live. Any non-empty value other than `0` selects the value-phase variant of the split-K pass 1 (`shaders/sdpa_decode_split_p1v.comp`) when `MLX_OMARCHY_SDPA_DECODE_SPLIT` routes a decode step to the split route. The variant reads V in 8-byte loads: 32 lanes cover the 128 dimensions in groups of four and the four subgroups each walk 32 of the 128 keys of the block, so the chain of dependent loads is 32 keys long instead of 128, and the four partial sums of a dimension are added in a fixed order. It needs the V element offset, head stride and key stride to be multiples of 4; otherwise the old pass 1 runs. Pass 2 and the scratch layout are shared. `0` keeps the old pass 1 at every length. Unset follows the part rule `sdpa_split_pv_max_keys` in `device.h`: the variant runs from the first split-route length up to 2048 keys on G14C and G13C (it saves about 19 microseconds of the flat floor there and loses above 4096 keys), and never on G13G. Qwen3-4B decode at 477 prompt tokens: +4.6 percent on G14C, +4.7 percent on G13C. |
| `MLX_OMARCHY_GDN_GQA_BF16A` | unset (off) | Read live. `1` gives a bf16-A_log model (the Qwen3.8 family) with Hk != Hv (27B: 16 key heads, 48 value heads) the same native key-head indexing that the f32-A_log route has: the decode kernel `GatedDeltaDecodeBF16Gqa` (the default arithmetic order plus the key-head index, built from `shaders/gated_delta_decode.comp` with `-DGDN_NATIVE_GQA_INDEX`) reads key head j / (Hv / Hk) itself, so the backend records no q and k expansion copies, two fewer dispatches per linear layer per token. The output and state equal the expanded route and the caller-repeated route bit for bit in the test (`tests/omarchy/test_gdn_gqa_bf16a.cpp`, llvmpipe); device bit equality has to be shown on the target device before a default changes. Needs the tiled decode kernel (not the legacy G13 walks) and raw gates mode. |
| `MLX_OMARCHY_GDN_PF_GQA` | on for G14C and G13C, unset elsewhere | Read live. Selects, on an f32-A_log model (the Qwen3.5-9B route) with Hk != Hv, the decode kernel `GatedDeltaDecodeBF16PfComposedGqa`: the untiled prefetch kernel in composed order plus the key-head index (built from `shaders/gated_delta_decode_perrow_pf.comp` with `-DGDN_NATIVE_GQA_INDEX`), which reads key head j / (Hv / Hk) itself, so the backend records no q and k expansion copies, two fewer dispatches per linear layer per token. Default: on where the device name contains G14C (M2 Max) or G13C (M1 Max), the parts where it was measured (`receipts/2026-10-18-gdn-pf-gqa/` and `receipts/2026-10-18-gdn-pf-default/`: bit-equal to the tiled kernel on the 9B, about 8 percent faster decode on both); every other part keeps its previous default (the tiled composed kernel, and on a G13 part other than G13C the untiled composed prefetch kernel with the expansion copies). `0` turns it off (the tiled kernel again on G14C and G13C); `1` also turns it on where `MLX_OMARCHY_GDN_DECODE_TILE=0` or a legacy G13 part has the tile off. An explicit `MLX_OMARCHY_GDN_DECODE_TILE` (`1` the tiled kernel, `0` the untiled kernel with the expansion) overrides the default; `MLX_OMARCHY_GDN_PF=0` and `MLX_OMARCHY_GDN_GQA_DECODE=0` also take the route off it. It needs the prefetch kernel's alignment (the h0 and hf offsets multiples of 4); outside that the route keeps its previous default. Models with a bf16 A_log (the Qwen3.8 family) never take it: their route is `MLX_OMARCHY_GDN_GQA_BF16A`. The output and state equal the expanded route and the caller-repeated route bit for bit in the test (`tests/omarchy/test_gdn_gqa_bf16a.cpp`), which also names the default kernel by enum for the part that runs it. |
| `MLX_OMARCHY_GDN_PF_WIDE` | on for G14C and G13C at equal head counts (Qwen3.8-2B), off elsewhere | Read live. `1` runs the untiled prefetch GDN decode kernel with thirty-two state words in flight per memory round trip (`GatedDeltaDecodeBF16PfWide`, `shaders/gated_delta_decode_perrow_pf.comp -DGDN_PF_WIDE`) instead of eight. Any other set value runs the plain prefetch kernel. Unset, the wide kernel is the default where the untiled default of `MLX_OMARCHY_GDN_DECODE_TILE` holds at equal head counts (G14C and G13C, Qwen3.8-2B); every other shape keeps the plain kernel. Default arithmetic order (bf16 A_log models), Dk a multiple of 32, and only where the untiled prefetch kernel runs. The fma chain and the stores are the plain prefetch kernel's, element for element, so its outputs equal the plain kernel's bit for bit (`tests/omarchy/test_gdn_gqa_bf16a.cpp`). |
| `MLX_OMARCHY_GDN_DECODE_TILE` | by part and route | Read live. `1` selects the tiled GatedDeltaUpdate decode kernel, `0` the untiled prefetch kernel. Unset: tiled except on a legacy G13 part (a G13 device that is not G13C), which runs untiled; on G14C and G13C the f32-A_log route (Qwen3.5-9B) runs the untiled prefetch kernel with native GQA (`MLX_OMARCHY_GDN_PF_GQA`); on G13C a bf16-A_log model with Hv == 2 * Hk, Hv == 3 * Hk or equal head counts, and on G14C one with Hv == 3 * Hk or with equal head counts (Qwen3.6-35B-A3B: 16 key heads, 32 value heads, G13C only; Qwen3.8-27B: 16 key heads, 48 value heads; Qwen3.8-2B: 16 and 16 heads, G14C and G13C) runs the untiled prefetch kernel `GatedDeltaDecodeBF16Pf` (with the expansion copies where the head counts differ), when the prefetch kernel's alignment holds (the h0 and hf offsets multiples of 4; otherwise the tiled kernel); another part or head ratio (G14C at Hv == 2 * Hk was not measured) keeps the previous default. With the tile switch unset, `MLX_OMARCHY_GDN_PF=0` or `MLX_OMARCHY_GDN_GQA_BF16A=1` keep the tiled kernel on that route; `MLX_OMARCHY_GDN_DECODE_TILE=0` with `MLX_OMARCHY_GDN_PF=0` runs the scalar untiled kernel. The bf16-A_log default is about 8 percent (ratio 2) and 5.8 percent (ratio 3) faster in decode on the 16-inch M1 Max and about 6 percent (ratio 3) on the 14-inch M2 Max, and is not bit-equal to the tiled kernel; teacher-forced NLL on 128 prefixes is not worse by more than 0.02 nats at 2 SE for each measured pair (`receipts/2026-10-19-gdn-bf16a-untiled/`, `receipts/2026-10-20-gdn-bf16a-ratio3/`, `receipts/2026-10-20-gdn-bf16a-g14c-ratio3/`). |
| `MLX_OMARCHY_QMM_VEC_Q4_WORD` | on | Packed q4 word path in qmm gemv (xpack). `0` reverts to scalar; may change which ulp-level near-ties flip. |
| `MLX_OMARCHY_INT8_NAIVE`, `_INT8_IMAD`, `_INT8_F32FMA` | f32-FMA on its gate | Route pins for `mx.fast.int8_matmul`. Default: the scalar f32-FMA kernel (`shaders/int8_matmul_f32fma.comp`) when `k % 4 == 0` and `32 <= group <= 1024`; everything else keeps the int32 tiled kernel. Exactness: f32 group sums are exact and addition-order-independent while every partial sum stays <= 2^24, and the worst int8 product is `(-128) * (-128) = 16384`, so `16384 * 1024 = 2^24` is the exact bound (an earlier 16129 bound used 127*127 and undercounted; groups above 1024 can flip low bits and stay on int32). `_INT8_IMAD=1` forces the tiled kernel, `_INT8_F32FMA=1` pins the f32 route (it cannot widen the gate), `_INT8_NAIVE=1` forces the retired naive kernel as the A/B kill switch. All shipped routes are bitwise-identical on the legal input domain: 161/161 A/B assertions vs naive on G13C including the 2^24-boundary extremes and a poison test. 16-inch M1 Max (G13C), 2026-10-08: 332 GMAC/s at the DiT shapes vs 92.6 on the tiled arm. |
| `MLX_OMARCHY_QMM_TILE` | enabled | `0` disables the tiled quantized-matmul route. |
| `MLX_OMARCHY_QMM_TILE_RB` | enabled | `0` disables row blocking in the tiled quantized-matmul route. |
| `MLX_OMARCHY_QMM_COOPMAT_WG_PER_CORE` | `6` | Workgroup-per-core floor for cooperative-matrix tile selection. `0` disables the grid-based step-down; malformed values keep the default. |
| `MLX_OMARCHY_GREEDY_PRUNE_TEST` | unset | Qualification only. `full` forces `mx.fast.greedy_quantized_argmax` onto its full exact path (every row, logsumexp, subtract, argmax); `keep` keeps every row as a survivor. Token-neutral by construction (receipt 2026-09-23-vocab-prune). |
| `GDN_FALLBACK_DEBUG` | unset | Prints fused-eligibility inputs for the GDN prefill route when set. |

## mlx-lm serve patches (vendored in `patches/`, applied by
`scripts/apply-mlx-lm-patches.sh`, wired into `install.sh`)

- `patches/mlx-lm-0.32/` — the same series rebuilt for the mlx-lm 0.32 API
  line (commit 94cdcae, the pin oMLX uses; the PyPI 0.32.0 wheel carries
  byte-identical patch-site files), so oMLX can run on the Omarchy
  stack. The apply script picks it when `mlx_lm.generate` defines
  `StopSequences`. conv-ring has no 0.32 port; the script refuses
  `MLX_OMARCHY_CONV_RING=1` there before touching the venv. Receipt:
  receipts/2026-10-02-mlx-lm-032. Token note: the 0.32 stack does not
  reproduce the 0.31.3 stack bit-for-bit on every prompt (upstream
  rescaled the q/k-norm eps, and the raw decode route is conditional);
  on the T6001 10-prompt contract corpus, 3/10 Qwen3.8-2B prompts flip
  one near-tie token. The quality gate (harness v2 GSM8K/IFE vs the
  shipping stack) passed within its pre-declared noise band, which is
  what the acceptance bar below requires for a token change; 4B/9B are
  bit-identical and perf is neutral.
- `mlx-lm-gated-delta-fast-route.patch` — **default ON.** Routes
  `mx.fast.gated_delta_update` in mlx-lm 0.31.3 to the fused kernel in the
  mlx-omarchy wheel. Required for the measured serve numbers.
- `patch-mlx-lm-gdn-raw-repeat.py` — **default ON on all chips.** The
  Qwen3.5-9B fused raw decode route (+31-35% on G14-class; +35-43% on G13)
  runs at Hk != Hv inside the backend: the tiled decode kernel on the f32
  A_log route reads key head j / (Hv / Hk) itself (on G14C and G13C the untiled
  prefetch kernel does, see `MLX_OMARCHY_GDN_PF_GQA`), and
  `MLX_OMARCHY_GDN_GQA_DECODE=0` makes the backend expand q and k instead.
  `MLX_OMARCHY_GDN_RAW_REPEAT=1` expands them in Python before the call. The published-wheel
  audit measured 99.51% teacher-forced agreement; all first free-run
  divergences were within one bf16 ULP. See docs/numerics-gate.md for the
  criteria and receipts/2026-10-04-gdu-bar-audit/README.md for evidence.
- `mlx-lm-convring.patch` — **default OFF.** Rolling conv-state ring; enable
  per venv with `MLX_OMARCHY_CONV_RING=1 scripts/apply-mlx-lm-patches.sh
  /path/to/venv`.
- `mlx-lm-greedy-prune.patch` — **default ON** (13-inch M1 A/B in
  receipts/2026-09-23-vocab-prune.md). Greedy decode steps
  (default sampler, no logits processors, one input token) of tied
  4-bit/group-64 Qwen3.5-family heads take `mx.fast.greedy_quantized_argmax`:
  a certified bound on a 3-bit code sketch skips the rows that cannot hold
  the argmax, so the token equals `argmax(logits - logsumexp(logits))`
  bit for bit while most of the vocabulary projection is never read.
  `logprobs` stay lazy and run the full projection only when a consumer
  evaluates them. Kill switch: `MLX_OMARCHY_NO_GREEDY_PRUNE=1` at run
  time restores the upstream step exactly. The sketch holds 3 bits per
  code, three quarters of the packed codes (190.7 MB for Qwen3.8-2B's
  248320-row head), built once per process at the first greedy call.
- `mlx-lm-server-skip-logprob-read.patch` (0.32 series only) — **default
  ON.** The server's decode loops read the sampled token's logprob off the
  device for every token — a gather graph plus a blocking `.item()` read,
  3.48 ms/token of the 19% serve-loop decode gap on a 13-inch M1 with
  gemma-4-E4B (receipt `receipts/2026-10-18-serve-loop-13inch/`) — even when the request asked for neither `logprobs` nor
  `top_logprobs > 0`; the handler reads `Response.logprob` only when
  `logprobs` is set and `Response.top_tokens` only when `top_logprobs >
  0`. The per-request flag rides the existing `batch_results` entry (and a
  hoisted local on the single path); skipped Responses carry
  `logprob=None` / `top_tokens=None`. Generated token ids are unchanged
  (`tests/test_server_logprob_skip.py` drives the real ResponseGenerator
  on the CPU tiny model). Kill switch `MLX_OMARCHY_SERVER_LOGPROB_READ=1`
  (read once at import) restores the upstream always-read; the 0.31.3
  series keeps upstream behavior.
- The patches are idempotent and fail loudly on mlx-lm version drift.

## Acceptance bar
