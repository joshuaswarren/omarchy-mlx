# Private ANE runtime

The ANE runtime copies the manifest into a sealed memory file, parses the ordered payload names from those exact bytes, copies each named payload into a sealed memory file through the same opened bundle directory, and validates that immutable snapshot. It then starts `mlx-omarchy-ane-worker` as a separate process. The worker receives only the sealed descriptors. Its readiness reply must match the graph hash, raw manifest hash, and payload-collection model hash validated by the parent. The worker owns the canonical `joshuaswarren/omarchy-ane` handles, mapped buffers, kernel bindings, and ordered program dispatch. The parent process owns host staging and the control socket. There is no Vulkan, CPU, or simulated fallback inside this runtime.

Build with `BUILD_SHARED_LIBS=ON` and `MLX_OMARCHY_ANE_SOURCE_DIR` set to a clean checkout at `6fa243ac7241119a9eb229abbf8cb4dd8949f915`. Static libmlx builds remain supported when the private ANE runtime is disabled; configuring that runtime against static libmlx is rejected because an archive has no loaded image from which to derive a worker installation prefix. Configuration fails for another commit or a dirty tracked tree. The build compiles libane with `LIBANE_CONFIG_STRICT_BIND`, so a bundle whose task stream names no per-surface channel map (a positional map) is refused at load, matching the strict bundle validator. Installed callers resolve `mlx-omarchy-ane-worker` under the prefix of the libmlx image that the process actually loaded. The installed worker loads the sibling `lib/libmlx.so` through an `$ORIGIN/../lib` runtime path, so it does not depend on a caller-specific library search path. The generated build-tree worker is eligible only when that image canonicalizes to the exact generated libmlx target; otherwise a missing installed worker fails closed.

Install an ANE-enabled wheel with `bash install.sh --ane`. This explicit mode installs and applies `mlx-omarchy-ane.conf`, creates the shared `/run/lock/mlx-omarchy-ane` directory with mode `01777`, and creates lock and quarantine files with mode `0666`. It does not require a render-group membership. If an old root-owned file cannot be opened to repair its mode, the runtime uses a private lock and quarantine under the user’s `XDG_RUNTIME_DIR`. The default GPU-only install does not require ANE or host-global ANE state. Clean release truncates the quarantine file instead of replacing its inode.

Call `AneRuntime::load(bundle, startup_deadline, diagnostic_path)` with a positive deadline and a writable diagnostic path. One absolute monotonic deadline covers snapshotting, validation, process start, and readiness. `execute` requires the exact input names and byte counts declared by the bundle. Each execute or shutdown call owns the shared staging buffer, serial, control socket, and lifecycle state for its complete transaction; synchronized accessors return copies where needed. The worker keeps program handles, physical input/output allocations, state, and intermediate buffers alive across calls. It resets outputs and intermediates for each execution, packs logical fp16 tensors with the declared NCHW plane and row strides, checks the caller deadline immediately before every input transfer and program execution submission, executes every program in `dispatch_plan` order, and copies only declared graph outputs back to the parent.

Every execute and shutdown transaction uses one absolute monotonic deadline from public API entry. The runtime holds a host-exclusive file lock that is inherited by the worker. It also writes the current boot ID before process start. A clean shutdown or a confirmed pre-submission failure clears that state. An uncertain completion preserves it, so a later process cannot create another runtime until reboot changes the boot ID. A command-send failure closes the control channel immediately and records `current_operation_submitted=false` without claiming a hardware recovery requirement. A completion timeout, `ane_exec` error, partial multi-program dispatch, reply mismatch, or uncertain shutdown records `current_operation_submitted=true`, marks the runtime unusable, closes the control channel without signaling the worker, and requires reboot before more ANE submissions. Live child processes are handed to a nonblocking process-lifetime reaper, so a timed-out API call returns without losing eventual `waitpid` ownership.

`shutdown` clears all worker-owned program handles, waits for process exit within its deadline, clears host ownership state, and returns the worker PID and released-program count. Only a returned receipt confirms clean release. A failure before its command is sent is classified as a confirmed pre-submission failure. A failure after submission is uncertain and preserves the boot-scoped quarantine.

The worker accepts only a per-ABI lane selected by `MLX_OMARCHY_ANE_ABI` (default `1`). The selected lane must match the host AND the bundle's declared `driver_abi_major`; otherwise the worker refuses before opening the device.

| ABI | Lane name | DT compatible | Module | Driver ABI check | Pinned libane commit |
| --- | --- | --- | --- | --- | --- |
| `1` (default) | M1 / T8103 / T6001 | `apple,t8103-ane` / `apple,t6000-ane` | `ane` | DRM version ioctl major must be `1` | `6fa243ac7241119a9eb229abbf8cb4dd8949f915` |
| `2` | M2 / T6021 | `apple,t6021-ane` | `ane_t6021` | DRM version ioctl major must be `2` | `8b010938aeb64bfa04b95e89da0bedd2ef9e3e72` |

Every lane additionally requires: Linux AArch64, device-tree ANE node status `okay`, bound `ane` platform driver, runtime PM `active` (the gate opens the device first, so a runtime-PM-managed node with `power/control=auto` resumes; `on` control is accepted too; a non-active status is refused), and a readable+writable `/dev/accel/accel0`. The lane is exclusive — a per-ABI pin (libane commit, module name) never satisfies a request for the other lane, and an `MLX_OMARCHY_ANE_ABI=N` worker refuses a bundle whose `driver_abi_major` is not `N`. The bundle manifest parser also refuses a target/abi mismatch: `compiler.target=h13` requires `driver_abi_major: 1`, `compiler.target=h14` requires `driver_abi_major: 2`.

The runtime identity records the graph hash, raw manifest hash, payload-collection model hash, kernel, module source version, libane commit, the active ABI lane, and the matched DT-compatible string. The worker queries `DRM_IOCTL_VERSION` and requires the driver's ABI major to match the runtime ABI. Missing or mismatched values produce a compatibility error.

Lane 3 (driver ABI 3, H16) does not use this runtime. Its schema-5 bundles
run through the bounded worker CLI with `--device h16` (`docs/ANE-LINUX.md`);
the `MLX_OMARCHY_ANE_ABI` gate above accepts only `1` and `2` and refuses a
schema-5 bundle through its `driver_abi_major` cross-check. The only change
here is the manifest version refusal, which now names both supported
schemas: `unsupported manifest_version (expected 4 or 5)`.
