# q4-bw-bench: first G17C measurement of the wAN 40x320 q4 GEMV variant

2026-11-19, m5max (asahi, Apple M5 Max G17C B1, subgroupSize 32), branch
wAN/q4-gemv-m5 @ 84679e7ec, bench built on the M5 (/tmp/wan-q4gemv worktree),
run under /tmp/m1-gpu.lock, reps 21, two legs. Shape k=2560 n=320, bytes
517760 = the ceiling table's with-metadata count. eq screen: 0 bit mismatches.

Device peaks measured in-run (Main's 165 GB/s figure is half the real device):
- copy 319.7 GB/s (med GPU), read 317.0 GB/s. Roof for this shape at the
  measured copy peak: 517760 B / 320 GB/s = 1.62 us.

Shape result (GPU-timed medians):
- base (production general-affine, grid 40): 131.5 us
- m5 variant (40 WG x 320 threads, 8 rows/WG, uint4 = one q4 group/load,
  full-k stream, threadgroup reduce): 38.6 us (min 36.3) = 3.4x over base
- wall medians carry the known ~27 us in-dispatch pollution (2.1-2.2 GB/s wall)

Verdict: the decomposition wins 3.4x over the harness base but sits ~24x above
the measured roof - the shape runs ONE wave (40 WG) and each thread chains 40
uint4 loads, so DRAM latency is not hidden. Named next lever: split k (4x more
workgroups, threadgroup partials, two-pass or atomic combine) to put several
waves in flight, or software-pipeline the load chain. The ceiling table's
GB/s floors should be restated against the measured 320 GB/s (floors halve).
