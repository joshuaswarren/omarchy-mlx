# M2D-7 audit — M2 GDN decode consolidation on 2B/9B: delivered by the merged #1038–#1070 series (w7H, 2026-11-27)

The row's premise predates a week of merged GDN work. This audit checks each
clause of M2D-7 against current `main` (`9c9304b108`) and finds every item
already delivered with bit-exact tests, G14C 5-pair ABBAs with identical
greedy ids, and cross-model review. No new PR is warranted; optimizing the
named kernel would be dead work — it is no longer the dispatched route.

## Clause-by-clause

**"Audit whether `GdnConvDeltaUpdate` (`GDN_CONV_DELTA=2`) actually fires on
all 18 2B GDN layers (check `!apple_norm` / `dense_inputs` guards)"**

- `!apple_norm` can never block the fused route today: the guard evaluates
  `apple_norm_enabled(device, row_length=128, B*C)`, and
  `apple_norm_shape_selected` only selects 256/2048/2560/4096 — 128 is not in
  the list, so it returns false on every part. The guard is vestigial for
  this op.
- The remaining guards (`B==1`, `K==4`, dense inputs + 4-aligned h0 offset,
  Sg32 capability) are layer-independent — the per-layer graph produces the
  same shapes, so the route fires uniformly on all 18 layers.
- Landed proof: #1043's GPU test asserts the coalesced kernel's dispatch
  count (`on.dispatches == 1` vs `off.dispatches >= 3`) with
  `MLX_OMARCHY_GDN_REQUIRE_ENGAGED=1`, 14/14 cases / 465 assertions.

**"Eliminate residual `CopyGeneral` copies around GDN"**

- The coalesced Sg32 route (the dispatched one, below) allocates the three
  outputs fresh and reads the dense inputs in place — no copy sites. The
  decode-window census (DEC-28, jw16) measured zero CopyGeneralBF16; #1043's
  bit-exact `array_equal` checks on all three outputs bound the correctness.

**"Optimize `GatedDeltaDecodeBF16PfWide` register/state traffic"**

- Superseded: on G14C (the M2) current main routes these models to the
  coalesced Sg32 family — the dispatch ends with `GatedDeltaDecodeConvNormBF
  16Sg32[Fast]` whenever `gdn_coal_sg32_ok` holds; PfWide is only the
  fallback on devices without subgroup-32. Optimizing it is dead work. The
  traffic work landed where the traffic actually is: #1070 (hoisted Sg32Fast
  conv+state and Phase-3 loads, +0.44% 2B), #1068 (+1.50% 2B, +0.60% 9B).

**"Extend `GdnConvDeltaUpdate` to 9B ratio-2 GQA (`Hk=16/Hv=32`)"**

- Landed: #906 (engage ratio-2 on the mode-2 route), then #1043 —
  `f32 A_log` + native GQA key-head indexing (`head / (Hv/Hk)`) routed to one
  `GatedDeltaDecodeConvNormBF16Sg32` dispatch, collapsing 3 dispatches to 1:
  **−48 dispatches and −48 barriers per token** on 9B (beats the row's −72
  disp/tok estimate, which assumed replacing two kernels with one without
  counting the norm fold), with 14/14 bit-exact test cases and the measured
  5-pair G14C ABBA: 9B ctx512 +3.27% median (58.67 → 60.58 tok/s), 5/5 pair
  wins, greedy ids bit-identical (`cedd5549b251572a`); ctx2048 +3.02%, 3/3,
  ids `5b327e139ad9b881`.
