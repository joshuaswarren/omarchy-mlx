This verifies the patch application and static import gate on the clone, not a full package install or runtime.

Before changing `packaging/omlx-linux/install.sh` and `apply-platform-gate.sh`, update both pin references to the selected upstream SHA; the patch application and exact static import scan already passed on that SHA. Then run the Linux packaging/import/API smoke, start the server on the dev box, and exercise one real completion plus cache and tool/API paths. On a Vulkan host, separately establish that the actual MLX wheel and Qwen model execute correctly; no such hardware run was performed for this triage. Do not use an M2 for this work.

**MLX #4516:** no analogous specialization is justified from the current evidence. The Vulkan single-row shader already chooses its one-word-per-lane path for N not divisible by 8. A follow-up should be an experiment, not a port: census real model weight N values and route selection; if a hot N%8!=0 workload reaches a slower multirow/general path, benchmark that path against a bounded row-tail variant. Validate all final-lane loads/stores, affine bias exactness for f16/bf16, and parity before accepting any speed result. The upstream 1.07–1.38x and 1.19–1.20x results are Metal-only references; no Vulkan speedup is measured here.
