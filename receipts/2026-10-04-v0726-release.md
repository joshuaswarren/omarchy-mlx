## Correction — 2026-10-04: 9B fused-route free-run claim did not reproduce

The claim below that the fused 9B route was default ON and produced
"bit-exact/order-matched 100% identity" did not reproduce on the published
v0.7.26 wheel. GduBar's 10-prompt x 512-token audit measured 29.43% prefix
identity; 6/10 first divergences had a composed top-2 gap of 0.125, above
the 0.05 near-tie cutoff. Per-op fp64 and S=1 PPL checks passed, but the
free-run bar failed. v0.7.27 turns the route OFF by default on all chips.
For v0.7.26, set `MLX_OMARCHY_GDN_RAW_REPEAT=0` to select the composed route.
Evidence: `receipts/2026-10-04-gdu-bar-audit/README.md`.

## Qwen3.5-9B fused GDN raw decode route, DEFAULT ON (+31..35% decode on the 9B)

Qwen3.5-9B (Hk<Hv: 16 vs 32, f32 A_log) previously fell through the fused
decode kernel's `Hk == Hv` gate into the composed per-token fallback
(~700 extra small dispatches/token). This cut ships the order-matched
kernel (`d86ea8815`: tiled GDU decode walks reproduce the composed C++
fallback arithmetic for A_log-f32 models behind shader flag bit 9) and
the installer wiring (`cd4a8c6f9`: `patch-mlx-lm-gdn-raw-repeat.py`
invoked by `apply-mlx-lm-patches.sh`, expanding q/k to the value-head
count; PatcherCoverageTests 26/26). Default ON; kill switch
`MLX_OMARCHY_GDN_RAW_REPEAT=0` restores the exact pre-land dispatch.

Numbers from receipts/2026-10-04-jw16-decode-dispatchfuse.md addenda 1-4
(all on the T6001 host, same-window pairs): 9B decode d64 37.50 tok/s default vs
28.49 kill switch (+31.6%); d512 36.47 default; order-matched kernel
keeps ~91% of the pre-order-match +34%. Teacher-forced gate (H244
methodology, 10 prompts x 512 teacher tokens = 5120 positions): top-1
agreement 99.39%, all 31 disagreements near-ties <= 1 bf16 ULP (max gap
1.0 ULP, mean 0.32), PPL delta -0.049%, per-op fp64 error bit-identical
to composed on captured real operands, free-run greedy identity 100%
(5 prompts x 512). Digest pins: d64 `26d569c8` / d128 `2bbf33d4` /
d256 `0279994b` unchanged; d512 re-pins `f36dab24` (free-run path).
2B/4B/27B untouched by construction (bf16 A_log keeps bit 9 unset;
27B is full attention, no GDN).

digest `e2c919be0fe285c6…` on the default arm AND under

Route-probe interpretation (recorded because the two lanes' surfaces
differ): DispatchFuse's fresh check ran on an UNPATCHED mlx_lm where the
kill arm reaches the backend's C++ composed fallback (their
`GDN-FALLBACK` lines). On THIS surface the installer patch is applied,
so the kill arm diverts earlier — at the python dispatcher
(`gated_delta_ops` soup, the 28.51 tok/s arm) — and the backend C++
fallback never runs in either arm (0 lines both, verified against the
probe site `primitives.cpp:11313`, which prints only from the C++
fallback). The route discriminators on a patched install are the
same-window rate collapse, the fused-entry wrap count (1776 default,
matching DispatchFuse's fused count exactly), the digest identity, and
the apply-level evidence above.

Formal pass: the corrected assertion set evaluated over the captured
