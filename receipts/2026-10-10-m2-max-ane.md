# M2 Max (T6021) ANE measured results

Linux, kernel 7.1.12-2-12.6-sep-ARCH except where noted. Driver module builds
named per line. What the receipts behind this file are: bit-exact fp16 batch
multiply, one whole-encoder run, a resident-model session, and latency rows.

## Driver state

- `ane_t6021 ca09ce8` loads, `/dev/accel/accel0` is present, and
  `mlx-omarchy-info` (installed omarchy-mlx 0.7.28-1) reports ANE available.

## Batch multiply, bit-exact, module `ca09ce8`

- 1, 2, 4, 8 jobs per call, 12 distinct input seeds per batch size, 5 runs: no
  mismatches against the half-away fp16 reference. Every output bit-exact.

## Whole Parakeet encoder, one fixture, one boot

- Kernel 7.1.13-3-1-ARCH, an earlier driver module than `ca09ce8`. One
  Apple-compiled whole-encoder program, median call 254.5 ms in two separate
  processes of 20 calls each (medians 254.497 and 254.517 ms). Output equals
  the fp16 golden. Not repeated on `ca09ce8`.

## Qwen3.8-2B decode, resident session

- 38 programs per step, driver modules `329b9da` and `ca09ce8`. 1.21 tokens
  per second resident against 0.157 per-call (7.7 times). Logits identical in
  both arms. The run is reproducible.
- Match to the reference: 3 of 10 prompts. The others diverge at the same step
  in repeat runs. This row claims resident ANE decode runs and is reproducible,
  not that it matches the reference everywhere.

## Add-program latency, module `37ffb57`

- Median 0.25 ms per call over 200 and 2000 calls. 33 of 250 calls above
  400 us (13.2 percent) in a pattern that recurs every 8 calls.

## Not proven on this chip

- No hybrid ANE and GPU split, no soak.
- The per-call load path under repeated loads: a second pass over the 38
  programs failed 5 times with a buffer-allocation error. The resident path is
  the supported fast path.
- No result on T8112 or T6022.
