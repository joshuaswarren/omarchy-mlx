## Run 2 (2026-10-10) identities and conditions

Source for every line below: the run's own raw log and ticket, read after the run. Where nothing was recorded the
line says so.

- Conditions of the timed cell: NOT a quiet machine. Other tickets ran on the same M2 around it: a standing test
  battery with GPU work (Vulkan) from another lane (parts 2 and 3, about 16:34:45 to 16:34:51Z overlapped the timed
  cell) and two ANE ladder tickets from the same lane as this run. The device calls were serialized by a file lock
  (`/var/tmp/ane-run.lock`, held by the 20-call process for its whole run), so no other ANE call was interleaved.
  GPU work from the other lane shared the SoC and DRAM. The bit-exact and token results do not depend on this. The
  253.5 ms median is therefore a number taken beside GPU work. It matches run 1 (254.5 ms) within 0.4 percent; the
  effect of the GPU work was not measured, and no claim is made about it.
- Command (line 85 of the run's own log, expanded). This is the line the validation step printed: a dry run prints
  the locked command instead of running it. The timed call builds its argument list with the same function, so only
  the dry flag differs, but the timed call's own argument list was not logged. This is the command as validated,
  not a logged copy of the executed line:

