# omarchy-mlx v0.7.44

[Joshua's agent]

This is the first release since v0.7.41. It fixes three comment-handling bugs in the custom-kernel translator, one of which stopped the Parakeet mel frontend on Vulkan, keeps a NaN a NaN in the bf16 conversion helper, adds opt-in speculative decoding with output identical to plain greedy, raises the default GPU submission budget on two chips, speeds up decode attention on the M1 Pro and the M2, and takes an O(N^2) scan out of the command encoder.

## What changed

- **Speculative decoding with exact greedy output, prompt lookup, and a draft-model fix (#431, contributed by fbalazsy).** `patches/mlx-lm-speculative-verify.patch` is applied last in the mlx-lm 0.31.3 series; the 0.32 line skips it. Each verify pass runs with full logits and the short-pass GEMV rows, which the PR reports match the single-token decode kernel bit for bit, so greedy speculative output is the plain greedy output. Before this, the draft-model path failed with `IndexError` on the first accepted draft token. Caches that cannot be trimmed (Qwen3.5 gated-delta and conv state) are restored after a rejected draft and the accepted tokens are replayed. With no draft model, `MLX_OMARCHY_PROMPT_LOOKUP=K` turns on prompt-lookup drafting through `stream_generate`; it is off unless you set it. The QMV short-pass cap is 8 on G16S (M4 Pro). The numbers in the PR (Qwen3-8B 4-bit and Qwen3.5-4B 4-bit on an M4 Pro, 256 greedy tokens; 0.97x to 1.91x depending on the prompt, identical to greedy in every case) were measured by the contributor, not by this release's gates. Receipt `receipts/2026-11-14-g16s-speculative-lookup`, docs `docs/kernel-flags.md`.
- **Three comment-handling fixes in the custom-kernel translator (#427, #430, #433).** After #420, five of the seven Parakeet mel kernels threw on Vulkan with `generated MSL has an unbalanced delimiter` although the kernel text is balanced. The helper-signature scan started its parenthesis search inside a comment (#427), the kernel-signature search did the same (#430), and a header comment naming a Metal-only construct made valid MSL throw `unsupported MSL feature` (#433, which strips comments from the user header before the passes). #427 was bisected host-side to #420 and was checked with a standalone build of the translator tests, not on a device. Other comment-blind `find('(')` searches may remain (tracked in #428).
- **Profiler records: an empty submit no longer takes a ring slot's dispatch records (#434).** Only the opt-in GPU profiling build is affected: per-submission counts and phase attribution were wrong when an empty submit followed a recording one. Dispatch totals were not affected. `profile_analyze.py` now exits 2 when a dispatch record names a submission that closed no command buffer.
- **The bf16 conversion helper keeps a NaN a NaN (#426).** After #420, some NaN inputs came out of the helper as inf, -0 or 0. The helper now returns the quiet NaN 0x7fc0. The tags v0.7.42 and v0.7.43 exist but were never released; v0.7.44 is the first release with this fix.
- **Apple M6 (G18G) default submission budget is 40000, not the 5000 fallback (#419).** `Apple M6 (G18G B1)` matched no row and took the fallback, which split every decode step into many small submissions. Measured before this release, on a wheel built before #420: Qwen3.8-2B decode 3.934 to 5.083 tok/s (+29.2 percent), Qwen3-4B 2.712 to 4.031 tok/s (+48.6 percent), outputs identical. Receipt `receipts/2026-11-13-g18g-batch-work`.
- **14-inch M2 Max (G14C) default submission budget is 100000, was 40000 (#422, #424).** Measured before this release: Qwen3-4B about +0.5 percent, Qwen3.8-2B about +1.3, Qwen3.5-9B about +1.4, first 64 ids identical, no frame over 33.3 ms beside decode. Other rows are unchanged. Receipt `receipts/2026-11-13-g14c-batch-work/REPICK.md`.
- **Split-K decode attention starts at 192 keys on the M1 Pro (G13S) and the M2 (G14G) (#415).** Before this, neither part had a row, so decode attention stayed on the fused kernel at every cache length. Measured on the v0.7.41 wheel with the split route off and on, a 443-token prompt and 128 greedy tokens: Qwen3-4B 4-bit decode 32.38 to 41.52 tok/s on the M1 Pro (1.282x) and 17.56 to 21.07 tok/s on the M2 (1.200x), tokens identical. Qwen3.8-2B 4-bit has few full-attention layers and does not gain: 74.43 to 73.97 tok/s on the M1 Pro and 39.39 to 39.16 tok/s on the M2, a ratio of 0.994 on both, and its greedy output changes (to the same new value on both) because the split route sums in a different order. Head width 256 decode attention takes the value-phase pass by default up to 768 keys on G13G and not on G13C (#403, #405).
- **The command encoder no longer scans every tracked range for each dispatch (#412).** The dependency tracker is indexed by buffer, so a dispatch checks only its own buffers.
- **`qmm_vec` loads scale and bias ahead of the 4-bit word dot (#414).** The arithmetic is unchanged; +0.5 percent on lm_head on the 16-inch M1 Max.
- **rms_norm at width 2560 is on by default on the 14-inch M2 Max (#401).**
- **Parakeet ANE detection accepts per-chip modules (#413).** A live T6021 ANE device is no longer refused.
- **The custom-kernel translator rounds the literal `bfloat16_t` type like Metal (#420).** Before, only the typename path rounded. This fixes the `kda_glue_pre` and `kda_glue_post` rows of the custom-kernel recheck. It changes the numerics of user-defined kernels that use that type; the stock decode path is not edited.
- Tests and docs: the f16 4-bit decode reference test sums in half-precision quads like the native kernel (#417); parity-run documents (#406, #409, #410).

## Known limitation

`mlx-omarchy-parakeet transcribe` can fail with `ModuleNotFoundError: No module named 'mlx'` if you run the packaged data file directly through `env python3` on a machine whose system Python has numpy and protobuf installed but not mlx. The CLI only hands over to the install's own Python when numpy or protobuf is missing, so with both present it stays on the system Python. Use the installed `mlx-omarchy-parakeet` launcher (it runs the install's Python), or run the file with the install's own `python3`. The fix, which makes the CLI check for mlx as well, is planned for v0.7.45. A machine whose system Python has neither package, as on a fresh image, is not affected.

## Measured

Gate results on the draft assets are below. The two budget lines above were measured before #420 merged, and the translator and speculative-decoding changes above were checked by their PRs, not on this release's wheel, so the pinned decode here is the check that this tag still gives the same output.

- Pinned decode on the uploaded aarch64 wheel, installed from the vendored set into a fresh venv on a 13-inch M1: Qwen3.8-2B 4-bit, greedy, seed 0, 128 tokens requested (127 timed), five separate runs. The generated-ids digest `sha256:775bf034e185c8f9` matched in 5 of 5 runs, the same digest the v0.7.34 to v0.7.37 release receipts record. Decode 27.62, 27.57, 27.60, 27.55 and 27.49 tok/s, median 27.57. This is an output-identity check, not a speed claim; I did not run the same bench on an older wheel, so there is no version-to-version speed number here.
- Release gates on the draft assets, run one at a time through the lab's GPU queue: clean install from the assets and the online Qwen3-4B card (g1, g3), codec and Kokoro (g6, g8), packaged Vulkan driver file, system install and speak queue (g7a, g7b, g9), and the ANE worker verification (g7c): all passed on the 13-inch M1. The system install (g7b) failed once because the test machine's temp directory was full of leftovers from an earlier build, and passed on the rerun after they were removed.
- Fresh-image Parakeet transcribe (g7d): the first run failed, and the cause is the known limitation above; that machine's system Python has numpy and protobuf. Run with a Python that has neither as `env python3`, as on a fresh image, it passed: transcript hash equal to the pinned golden, ANE mode on, zero CPU tensor events. The failed first run is kept in the gate record.
- GDN maskless correctness and the trig contract tests (g13, g15) were built and run from the tag's tree on a 14-inch M2 Max: all passed (the trig suite 49 of 49 assertions).
